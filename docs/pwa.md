# PWA, Accessibility & Mobile — PokéVerse Arena

PokéVerse Arena is an installable, offline-capable progressive web app, built
mobile-first and keyboard-accessible throughout.

## Installable PWA

| File | Responsibility |
| ---- | -------------- |
| [public/manifest.webmanifest](../public/manifest.webmanifest) | Name, `id`, colours, `standalone` display, PNG icons (192, 512, maskable) plus the SVG, and shortcuts to Adventure, Battle and Pokédex. |
| [public/icon.svg](../public/icon.svg), `icon-*.png` | Generated by `tools/gen-icons.mjs`; also the favicon and Apple touch icon. |
| [public/sw.js](../public/sw.js) | Hand-written service worker, stamped at build time. |
| [tools/postbuild.mjs](../tools/postbuild.mjs) | Runs after `npm run build`: writes a content-hash `BUILD_ID` and the app-shell file list into `sw.js`. |
| [src/index.html](../src/index.html) | Manifest, icons, Apple meta tags, CSP, theme colour, `viewport-fit=cover`. |
| [src/main.ts](../src/main.ts) | Registers `sw.js` — never on plain `localhost`, so dev HMR is untouched. |

The manifest keeps `orientation: any` so the installed app is not locked; rotation follows the device.

### Caching strategy

- **Install:** precache `index.html` and every script/style it references, so the *first* visit is already offline-capable.
- **Navigations:** network-first, falling back to the cached shell.
- **Hashed JS/CSS:** stale-while-revalidate in a cache named by build id, so each deploy starts clean.
- **Other same-origin files** (tilesets, icons): stale-while-revalidate in a stable cache.
- **PokéAPI data and sprite CDNs:** cache-first, size-capped (oldest entries evicted).

Only `response.ok` answers are cached; old caches are purged on activate. When a new build takes over, the app offers a reload
instead of showing a "failed to fetch module" error. `npm run e2e:offline` proves the app starts without a network.

### Security headers

`index.html` carries a Content-Security-Policy (`'unsafe-eval'` is required by PixiJS' shader compilation) and
`referrer`/`color-scheme` hints. GitHub Pages cannot set response headers, so the policy lives in a `<meta>` tag.

## Accessibility

- A keyboard **skip link** (visible on focus) jumps straight to `#main-content`.
- The navigation toggle exposes `aria-expanded` and an `aria-label`; decorative
  icons are `aria-hidden`.
- Interactive controls are real `<button>`/`<a>` elements with visible focus.
- Every animation is gated behind `prefers-reduced-motion`, including the PixiJS
  battle effects and the Three.js hero (which never initialise when reduced
  motion is requested); animated GIFs start as still images.
- Dialogs use the `pvModal` directive: focus trap, Escape, focus returned to the opener.
- HP bars are `progressbar`s, type badges meet WCAG AA contrast, toasts are `role=status` and pause on hover/focus.
- Hover effects only apply on devices that can hover (`@include hover-capable`).
- The whole UI is available in English and German (see [i18n.md](i18n.md)).

## Mobile-first

All feature styles start from the single-column mobile layout and progressively
enhance with the shared `@include up(sm|md|lg|xl|xxl)` breakpoints — see
[mobile-first.md](mobile-first.md) for the breakpoint scale and checklist.
